# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
I picked 4 of 5 because my query parsing and search logic relies on keyword matching, meaning that some unexpected phrasings or misspelled words in user queries might fail to yield a match even if a relevant item exists.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
5 of 5 is a reasonable and expected target because the condition checking if `search_results` is empty is purely deterministic code in the planning loop. If the list is empty, the loop must mathematically always branch and stop.

---

## 3. The selected item successfully passes to the outfit suggestion tool

The `id` of the listing stored in `session["selected_item"]` must be identical to the `id` of the `new_item` dictionary received by `suggest_outfit` in 5 of 5 successful tries.

**Why this target:**
State passing between the search phase and the suggestion phase relies entirely on python variables passing data within the loop. This process is 100% deterministic and shouldn't involve generative unpredictability, so 5 out of 5 is the required standard.

---

## 4. The fit card includes all mandatory details

The fit card generated by `create_fit_card` must explicitly mention the item's platform and its price in the final output text in at least 4 of 5 tries.

**Why this target:**
Because this tool relies on a generative model calling the prompt, it might occasionally skip the strict requirement to include specific fields despite instructions. 4 out of 5 accounts for the occasional model drift or hallucination, while enforcing that the prompt structure is solid enough to work well most of the time.

---

## 5. Price filtering is strictly enforced

If a user query specifies a max price, the returned `selected_item` must have a price less than or equal to that max price in 5 of 5 successful tries.

**Why this target:**
Price filtering is handled strictly by standard deterministic logic in `search_listings`. As long as the query parser extracts the price correctly, the tool should rigorously filter out items that exceed the limit. It should never fail this boundary condition.
